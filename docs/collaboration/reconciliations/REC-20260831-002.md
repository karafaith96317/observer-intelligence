## Confirmed attack findings

GROK-ATTACK-002 established three executable failures in GEM-IMPL-001:

1. **T02b / dependence failure** — distinct content hashes could receive unsupported independence credit despite a shared upstream narrative.
2. **TOCTOU / grounding-set drift** — authorization could survive deletion of primary evidence when the token bound only a convenient subset.
3. **Completeness gaming** — resolvability alone could yield `SUPPORTED` for evidence with no explicit claim-specific grounding.

The original adversarial record is preserved at `docs/collaboration/attacks/GROK-ATTACK-002.md`.

## GEM-IMPL-002 remediation

`src/oi_runtime_v0_2.py` adds the following development controls:

- explicit `upstream_source_id` provenance on observations;
- refusal of independence credit when multiple observations have unknown upstream provenance;
- containment when multiple observations declare the same upstream source;
- typed `EvidenceGroundingLink` records bound to an exact `target_claim_id`;
- separate resolvability and relevance scores;
- full `primary_evidence_hashes` retained on the reconciliation record;
- deterministic reconciliation snapshot binding claim, state, full primary set, and grounding links;
- token-to-reconciliation **exact evidence-set parity** at authorization time;
- execution-time re-resolution of the entire primary grounding set;
- snapshot recomputation and token snapshot parity before execution.

## Hardened falsification suite

`tests/test_grok_attack_002.py` now asserts safe containment rather than vulnerable behavior.

Coverage includes:

- shared-upstream soft-Sybil containment;
- unknown-upstream / no-independence-credit containment;
- post-mint primary-evidence deletion;
- cherry-picked token evidence subset;
- irrelevant-but-resolvable evidence gaming;
- SUPPORTS link aimed at the wrong proposition;
- one positive supported control path to ensure the runtime is not trivially deny-all.

## Schema conformance evidence

`tests/test_schema_fixtures.py` separately validates the repository's actual Draft 2020-12 JSON Schema contracts with positive and malformed fixtures. This is intentionally separate from runtime-unit tests because the JSON Schema vocabulary and Python dataclass vocabulary are not yet identical.

## Boundary / residual risk

This remediation closes the **demonstrated development-runtime exploits**, not all possible variants:

- `upstream_source_id` is provenance input, not an oracle. Deliberately falsified independent provenance can still evade exact clustering; unknown provenance is therefore denied independence credit, but externally verified provenance remains future work.
- Claim-specific grounding links are explicit assertions. The runtime verifies linkage structure, not semantic truth by itself.
- HMAC/shared-secret signing and in-memory nonce state remain development-only under GPT-SPEC-002.
- Persistent replay state, issuer trust roots/revocation, measurement-integrity tiers, T08 freshness/staleness, and stronger graded dependence estimation remain follow-on hardening.
